# Milestone 5: Database (Week 5)

Due Friday of Week 5. It checks what was taught from Thursday of Week 4 through Wednesday of Week 5: relational
design, SQL CRUD, joins, aggregates, subqueries, CTEs, window functions, indexes and JDBC.

The library outgrows memory. The data moves into a relational database whose constraints protect it even when Java
code is wrong, the repositories talk JDBC, checkouts become transactions, and managers get SQL reports.

The database is an embedded H2 database in PostgreSQL mode: it runs inside the Java process and stores its file in
`data/`. There is no server to install. `./scripts/sql.sh` opens an SQL shell on it (`EXPLAIN SELECT ...;` works there).

## Repositories and transactions (5C, 5D)

- Bind every value with a `?` parameter; never build SQL by joining strings with input.
- Close every `Connection`, `PreparedStatement` and `ResultSet` with try-with-resources.
- Wrap an `SQLException` in `StorageException` with the original as its cause. A constraint violation (SQLState
  starting with `23`) on add, update or delete becomes `RuleViolationException`. `updateEmail` applies the
  `Member.changeEmail` rules first.
- `checkout`: turn auto-commit off, mark the tool `ON_LOAN` only if it is `AVAILABLE`, insert the loan, read the
  generated id, then commit. Unknown tool: `NotFoundException`; unavailable tool: `RuleViolationException`. On any
  failure roll back, so the tool and loan tables never disagree.
- `checkin`: in one transaction, close the open loan (return date and fee) and set the tool's status.

## Reports (5E)

Each method's comment in `LibraryReports` gives its order. Use `GROUP BY` and `HAVING`, `LEFT JOIN` (categories
and members with nothing still appear), `NOT EXISTS`, a self-join on `members`, `COALESCE`, and for the top tools
a CTE with `ROW_NUMBER() OVER (PARTITION BY ...)`. `runQuery` is supplied.

## Memory or database (5F, 5H)

| Variable | Rule | Default |
| --- | --- | --- |
| `LANTERN_STORE` | `memory` or `jdbc` (any letter case, kept stripped and lower-case, so `" JDBC "` is stored as `jdbc`); otherwise `IllegalArgumentException` naming the variable | `memory` |
| `LANTERN_DB_URL` | must start with `jdbc:h2:`; otherwise `IllegalArgumentException` naming the variable | `AppConfig.DEFAULT_DATABASE_URL` |

`StoreFactory.open` returns the JDBC repositories plus `SqlReports` for `jdbc`, creating the tables and sample rows
only when they are missing. Then run the API on the database:

```bash
LANTERN_STORE=jdbc mvn -q compile exec:java -Dexec.args=serve
```
